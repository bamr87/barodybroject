Before this partial they hand-rolled the header and every one of them got it wrong the same way: `` with a filter input and no `class="sortable"`, so the filter worked, the sort affordance rendered, and clicking a column header did nothing. Contract with table_utils.js (both halves must hold, or the feature is dead): - `class="sortable"` is the exact selector table_utils.js:7 binds its click handler to. Without it no listener is attached. - `data-type="number"|"date"` selects sortTable's comparator (table_utils.js:56-62). A header with no data-type sorts lexicographically, which orders IDs 1, 10, 2. - The per-column filter is an `input.filter` nested inside its own ``; table_utils.js maps it back to a column via `input.closest('th').cellIndex` and ignores clicks originating inside it, so typing never re-sorts. This is the same markup `includes/model_table.html` emits. Prefer `{% render_model_table %}` whenever the table body fits its shape; reach for this partial only for the bodies that cannot.
